# 🔍 Real-Time Log Anomaly Detection System

A full-stack AI project combining Python, Kafka, ML (Isolation Forest),
Flask, and React to detect server anomalies in real time.

**Tech Stack:** Python · Apache Kafka · Isolation Forest · Flask · React  
**CS Concepts:** OS (IPC, process scheduling, signals) · TOC (regex / finite automata)

---

## 📁 Project Structure

```
log-anomaly-detection/
│
├── phase1_log_generator.py     # Collects real system metrics (OS: psutil, signals)
├── phase2_log_parser.py        # Parses logs with regex  (TOC: finite automata)
├── phase3a_producer.py         # Kafka producer          (OS: IPC, message queue)
├── phase3b_consumer.py         # Kafka consumer          (OS: blocking I/O)
├── phase3c_mock_stream.py      # Mock stream (no Kafka)  (for local testing)
├── phase4_ml_model.py          # Isolation Forest ML     (trains + saves model)
│
├── logs/
│   └── server.log              # Generated by Phase 1
├── data/
│   └── parsed_logs.csv         # Generated by Phase 2 (input to Phase 4)
├── models/
│   ├── anomaly_model.pkl       # Trained model (Phase 4 output)
│   └── scaler.pkl              # Feature scaler
│
├── KAFKA_SETUP.sh              # Kafka install instructions
└── requirements.txt            # All Python dependencies
```

## ⚡ Quick Start (5 minutes)

### Step 1 — Install dependencies
```bash
pip install -r requirements.txt
```

### Step 2 — Generate logs (Phase 1)
```bash
python phase1_log_generator.py
# Runs for ~60 seconds, then Ctrl+C to stop
# Output: logs/server.log
```

### Step 3 — Parse logs (Phase 2)
```bash
python phase2_log_parser.py
# Output: data/parsed_logs.csv
```

### Step 4 — Test streaming without Kafka (Phase 3 Mock)
```bash
python phase3c_mock_stream.py
# Simulates real-time producer → consumer flow
```

### Step 5 — Train ML model (Phase 4)
```bash
python phase4_ml_model.py
# Output: models/anomaly_model.pkl
```

## 🐋 With Real Kafka (Docker)

```bash
# Start Kafka
docker run -d --name kafka-local -p 9092:9092 \
  -e KAFKA_CFG_NODE_ID=0 \
  -e KAFKA_CFG_PROCESS_ROLES=controller,broker \
  -e KAFKA_CFG_LISTENERS=PLAINTEXT://:9092,CONTROLLER://:9093 \
  -e KAFKA_CFG_ADVERTISED_LISTENERS=PLAINTEXT://localhost:9092 \
  -e KAFKA_CFG_CONTROLLER_QUORUM_VOTERS=0@kafka-local:9093 \
  -e KAFKA_CFG_CONTROLLER_LISTENER_NAMES=CONTROLLER \
  bitnami/kafka:latest

# Terminal 1 — Consumer
python phase3b_consumer.py

# Terminal 2 — Producer
python phase3a_producer.py
```

## 🧠 CS Concepts Covered

| Concept       | Where Used                                      |
|---------------|-------------------------------------------------|
| OS — File I/O | `os.makedirs`, `open()`, `os.path` (Phase 1)   |
| OS — Signals  | `SIGINT`, `SIGTERM` handler (Phase 1, 3)        |
| OS — Scheduling | `time.sleep()` yields CPU (Phase 1, 3)        |
| OS — IPC      | Kafka = distributed message queue (Phase 3)     |
| OS — Process  | `os.getpid()`, `psutil.process_iter()` (Phase 1)|
| TOC — Regex   | Named group patterns → finite automata (Phase 2)|
| TOC — DFA     | `re.compile()` builds DFA internally (Phase 2)  |
| ML — Unsupervised | Isolation Forest, no labelled data needed  |
